# AI Future Radar v1.1.0

## Release policy

This release is automatically created only after the repository's **Production Closure Gate** succeeds. The gate requires three consecutive successful live production runs on the same application-code fingerprint, confirmed Telegram delivery, acceptable editorial/mission coverage, no duplicate publication, and provider/translation failures not being mislabeled as empty discovery. A merged pull request or green CI alone is not release acceptance.

## Editorial coverage

- Expand ongoing expert discovery to the 51-person registry while keeping the original 30-person bootstrap baseline separate.
- Search every watched expert through three bounded query families: long-form interviews/podcasts/talks/lectures, direct public posts/statements, and substantive activity/news.
- Allow up to two qualified, distinct expert voices in the three-story final portfolio; prefer coverage of two different people when both candidates pass source, evidence, freshness, Persian-language, and publication-quality checks.
- Recognize original X/Twitter posts as primary attribution only when the item actually resolves to X/Twitter; unverified scrape sources remain ineligible as first-party voice evidence.
- Apply separate one-item caps and selection penalties for genetics-led and medical/clinical-led news, rechecked at the confirmed-delivery boundary across editorial lanes.

## Runtime reliability

- Reconcile the pinned OmniRoute source lockfile before clean dependency installation.
- Require a parseable structured-JSON response from the `auto/smart` readiness smoke test before marking OmniRoute ready.
- Use a bounded 12-second request timeout and tolerate one transient read timeout before opening the circuit; connection and gateway failures still trigger the established fallback.
- Require topical content evidence for AI-core labels and exclude video-game entertainment while preserving legitimate game-theory research.

## Quality boundary

No source-evidence, Persian-language/naturalness, claim-alignment, freshness, duplicate-publication, Telegram delivery, or mission-coverage guard is weakened to fill a slot. The production closure workflow is the authority for deciding whether this release may be published.
